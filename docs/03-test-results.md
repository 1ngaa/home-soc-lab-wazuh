# Анализ событий

## 1. Проверка подключения Wazuh Agent

Для проверки подключения Windows-хоста к Wazuh Manager использованы данные командной строки и Wazuh Dashboard.

Результаты проверки:
- ID агента: `001`;
- имя агента: `DESKTOP-8D6DM90`;
- статус в Wazuh Dashboard: `Active`;
- версия Wazuh Agent: `4.14.8`.

Это подтверждает, что Wazuh Manager видит зарегистрированный Windows Agent и отображает его активный статус.

## 2. Анализ событий Sysmon

Для мониторинга активности процессов Windows используется Sysmon. Его события доступны в журнале `Microsoft-Windows-Sysmon/Operational`.

В журнале обнаружено событие `Event ID 1 — Process Create`, содержащее сведения о создании процесса. В событии присутствуют имя процесса, командная строка, родительский процесс, пользователь и хеш SHA-256.

События, связанные с обнаружением учётных записей и использованием PowerShell, также были представлены в оповещениях Wazuh. Это демонстрирует работу цепочки обработки событий:

`Sysmon → Wazuh Agent → Wazuh Manager → Alert`

**Скриншот:**
- [01-sysmon-installed.png](../screenshots/01-sysmon-installed.png)

## 3. Анализ оповещений Wazuh

В лабораторной среде проверены три сценария обнаружения. Для анализа использовались идентификаторы правил, уровни оповещений и сведения о событиях, отображаемые в Wazuh.

### 3.1. Ошибка аутентификации

**Правило:** `60122`  
**Level:** `5`

В Wazuh зафиксировано оповещение, связанное с ошибкой аутентификации.

Результат демонстрирует обработку события неуспешной аутентификации и отображение соответствующего оповещения в SIEM.

**Скриншот:**

### 3.2. Обнаружение учётных записей

**Правило:** `92031`

Зафиксировано оповещение, связанное с активностью обнаружения учётных записей (*Account Discovery*).

Соответствующая техника MITRE ATT&CK — `T1087 (Account Discovery)`.

Сценарий демонстрирует возможность выявления активности, связанной с поиском информации об учётных записях.

## 4. Анализ результатов сканирования Nmap

Для проверки сетевой доступности Windows-хоста из Kali Linux выполнено сканирование выбранных TCP-портов:

```bash
nmap -Pn -p 135,139,445,3389,5985,5986,80,443 192.168.56.102
```

Результаты сканирования:

| Параметр | Результат |
|---|---|
| Состояние хоста | `Host is up` |
| Задержка | `0.0014s` |
| Состояние проверенных портов | `filtered` |
| MAC-адрес | `08:00:27:51:E9:9F` |
| Производитель сетевого адаптера | Oracle VirtualBox virtual NIC |

Все восемь проверенных портов — `80`, `135`, `139`, `443`, `445`, `3389`, `5985` и `5986` — отображались в состоянии `filtered`.

Это означает, что Nmap не смог определить, открыты порты или закрыты, поскольку сетевой фильтр препятствует получению однозначного ответа. Результат сам по себе не позволяет установить точную причину фильтрации.
