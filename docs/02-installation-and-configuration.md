# Установка, настройка и диагностика лабораторного стенда

## 1. Подготовка среды

Для создания учебной SOC-лаборатории использовались следующие компоненты:

- Ubuntu 24.04.5 Desktop — сервер Wazuh;
- Wazuh Manager — централизованный сбор и анализ событий безопасности;
- Windows 10 — контролируемый конечный узел;
- Wazuh Agent 4.14.8 — передача событий с Windows на сервер;
- Sysmon 15.22 — регистрация системной активности Windows;
- Kali Linux и Nmap — проведение сетевых проверок;
- VirtualBox — запуск виртуальных машин.

Архитектура стенда, характеристики виртуальных машин и сетевые адреса описаны в [`01-architecture.md`](01-architecture.md).

## 2. Установка и подготовка компонентов

### 2.1. Подготовка Ubuntu

Сервер Wazuh размещён на виртуальной машине с Ubuntu 24.04.5 Desktop.

Перед настройкой выполнялось обновление списка пакетов:

```bash
sudo apt update
```

Затем обновлялись установленные пакеты:

```bash
sudo apt upgrade -y
```

При выполнении `apt update` возникли ошибки разрешения DNS-имён репозиториев `security.ubuntu.com` и `ru.archive.ubuntu.com`.

Команда `apt upgrade -y` установила обновления для 21 пакета. Ещё для 7 пакетов обновление было отложено из-за поэтапного распространения обновлений (phased updates).

### 2.2. Установка Wazuh Manager

Wazuh Manager был развёрнут на подготовленной виртуальной машине Ubuntu. Он используется для получения и анализа событий, поступающих от конечных узлов.

При настройке проверялись состояние службы менеджера, конфигурация сетевых компонентов и доступность портов, необходимых для взаимодействия с агентом.

Для проверки состояния службы используется команда:

```bash
sudo systemctl status wazuh-manager
```

На момент проверки служба имела статус `active`.

### 2.3. Установка Windows Agent

На конечном узле Windows 10 использовался Wazuh Agent версии `4.14.8`.

Агент предназначен для сбора настроенных событий на конечном узле и передачи их серверу Wazuh. После настройки подключения агент был зарегистрирован в системе и отображался в интерфейсе Wazuh со статусом `Active`.

Для просмотра списка зарегистрированных агентов на сервере используется команда:

```bash
sudo /var/ossec/bin/agent_control -l
```

В списке присутствовал агент:

- ID: `001`;
- имя: `DESKTOP-8D6DM90`;
- адрес в списке: `any`.

Статус агента также подтверждён в графическом интерфейсе Wazuh. Скриншот: [`03-agent-active-gui.png`](../screenshots/03-agent-active-dashboard.png).

### 2.4. Установка и настройка Sysmon

На Windows 10 использовался Sysmon версии `15.22`.

Sysmon регистрирует системные события, в том числе создание процессов. Эти данные могут применяться при анализе активности пользователей и программ.

В конфигурации Wazuh Agent присутствовала запись канала:

```xml
<location>Microsoft-Windows-Sysmon/Operational</location>
```

Это позволяет агенту собирать события из канала Sysmon, если соответствующая конфигурация применяется и канал доступен.

В журнале Sysmon было обнаружено событие `Event ID 1` (`Process Create`), связанное с запуском `conhost.exe` родительским процессом `cmd.exe`. В записи присутствовали сведения о командной строке, пользователе, родительском процессе и SHA-256.

## 3. Настройка и проверка Wazuh

### 3.1. Проверка конфигурации

В файле `/var/ossec/etc/ossec.conf` проверялись параметры компонентов передачи событий и регистрации агентов.

| Параметр | Значение |
|---|---|
| Порт передачи событий | TCP 1514 |
| Компонент передачи событий | `wazuh-remoted` |
| Порт регистрации агентов | TCP 1515 |
| Компонент регистрации | `wazuh-authd` |
| `queue_size` | `131072` |
| `use_source_ip` | `no` |
| `purge` | `yes` |

Для просмотра соответствующих параметров можно выполнить:

```bash
sudo grep -n -E '1514|1515|queue_size|use_source_ip|purge' /var/ossec/etc/ossec.conf
```

### 3.2. Проверка сетевых портов

Для просмотра TCP-портов, находящихся в состоянии прослушивания, используется команда:

```bash
sudo ss -lntp | grep -E ':1514|:1515'
```

В ходе диагностики были обнаружены процессы:

- `wazuh-remoted` — порт `1514`;
- `wazuh-authd` — порт `1515`.

### 3.3. Проверка ресурсов сервера

Для оценки доступных ресурсов виртуальной машины использовались команды:

```bash
free -h
```

```bash
nproc
```

```bash
df -h /
```

На момент проверки система располагала примерно 5,7 GiB оперативной памяти, четырьмя доступными процессорными ядрами и 46 GiB свободного места в корневой файловой системе. Размер swap составлял 4 GiB, использование на момент проверки — 0.

## 4. Сетевая проверка с помощью Nmap

Для проверки выбранных TCP-портов Windows с Kali Linux была выполнена команда:

```bash
nmap -Pn -p 135,139,445,3389,5985,5986,80,443 192.168.56.102
```

Параметры команды:

- `-Pn` — пропустить предварительную проверку доступности узла;
- `-p` — указать список портов для проверки;
- `192.168.56.102` — адрес конечного узла Windows в лабораторной сети.

Проверка позволила исследовать состояние выбранных портов в изолированной виртуальной среде. Фактические состояния портов следует описывать по выводу Nmap, а не только по факту выполнения команды.

## 5. Возникшие проблемы и диагностика

### 5.1. Ошибки DNS при обновлении Ubuntu

**Проблема:** при выполнении `sudo apt update` возникли ошибки разрешения DNS-имён репозиториев.

**Действия:** затем была выполнена команда `sudo apt upgrade -y`.

**Результат:** обновления для 21 пакета установлены, обновление ещё 7 пакетов отложено из-за phased updates.

### 5.2. Ошибки подключения Windows Agent

**Проблема:** в журналах Windows Agent фиксировались ошибки подключения и регистрации на портах `1514` и `1515`.

**Действия:** проверялись состояние Wazuh Manager, конфигурация сетевых компонентов и прослушиваемые порты сервера.

**Результат:** на сервере были обнаружены процессы `wazuh-remoted` и `wazuh-authd`. Активный статус агента впоследствии подтверждён в Dashboard; поступление и обработка событий подтверждаются оповещениями Wazuh.

### 5.3. Сообщение об ошибке базы данных

В журналах сервера встречалось сообщение:

```text
Unable to connect to socket 'queue/db/wdb'
```

При последующей диагностике процесс `wazuh-db` присутствовал в списке процессов. В дальнейшем работа Wazuh и поступление событий были подтверждены в интерфейсе системы.

## 6. Результаты обнаружения

В ходе тестирования были зафиксированы оповещения Wazuh, связанные с проверкой аутентификации, обнаружением учётных записей и активностью PowerShell.

| Rule ID | Сценарий | MITRE ATT&CK |
|---|---|---|
| `60122` | Authentication Failure | Не указана в данных правила |
| `92031` | Account Discovery | `T1087` — Account Discovery |
| `92027` | PowerShell | `T1059.001` — PowerShell |

Подробное описание сценариев и подтверждающие материалы приведены в каталоге [`screenshots/`](../screenshots/).

## 7. Итоги

В лаборатории подготовлена среда Wazuh, проверено состояние серверной службы, исследована конфигурация передачи событий и регистрации агентов. Windows Agent отображается в Dashboard со статусом `Active`, а поступление событий подтверждается оповещениями Wazuh.

С помощью Sysmon изучена регистрация создания процессов Windows. С помощью Nmap выполнена проверка выбранных TCP-портов конечного узла.

Лаборатория демонстрирует базовый цикл работы с событиями безопасности: сбор данных с конечного узла, передача в SIEM, формирование оповещений и первичный анализ их контекста.
