# Архитектура лабораторного стенда

## 1. Общая схема

Home SOC Lab — учебная лаборатория для изучения сбора, передачи и анализа событий безопасности с помощью SIEM-системы Wazuh.

Стенд развёрнут в Oracle VirtualBox и включает три виртуальные машины:

* **Wazuh Server** — Ubuntu 24.04.5 Desktop, сервер мониторинга.
* **Windows 10** — конечный узел с Wazuh Agent и Sysmon.
* **Kali Linux** — среда для проведения контролируемых сетевых проверок с помощью Nmap.

Логическая схема взаимодействия:

```text
┌───────────────────────────────┐
│           Windows 10          │
│                               │
│  ┌────────────┐ ┌───────────┐ │
│  │ Wazuh Agent│ │  Sysmon   │ │
│  └──────┬─────┘ └───────────┘ │
└─────────┼─────────────────────┘
          │
          │ Передача настроенных данных
          ▼
┌───────────────────────────────┐
│          Wazuh Server         │
│     Ubuntu 24.04.5 Desktop    │
│                               │
│  Приём и анализ событий       │
│  Обработка по правилам        │
└──────────────┬────────────────┘
               │
               ▼
┌───────────────────────────────┐
│        Wazuh Dashboard        │
│                               │
│  Просмотр событий и оповещений│
└───────────────────────────────┘


┌───────────────────────────────┐
│           Kali Linux          │
│                               │
│             Nmap              │
└──────────────┬────────────────┘
               │
               │ Сетевые проверки
               ▼
           Windows 10
```

Схема показывает основные логические связи между компонентами. Она не отражает все служебные соединения и внутренние компоненты Wazuh.

## 2. Компоненты лаборатории

| Компонент              | Роль в лаборатории                                    |
| ---------------------- | ----------------------------------------------------- |
| Oracle VirtualBox      | Запуск виртуальных машин                              |
| Ubuntu 24.04.5 Desktop | Операционная система сервера мониторинга              |
| Wazuh Server           | Приём, обработка и анализ поступающих событий         |
| Wazuh Agent            | Передача настроенных данных с Windows на сервер       |
| Windows 10             | Конечный узел для изучения системных событий          |
| Sysmon                 | Регистрация дополнительных событий активности Windows |
| Kali Linux             | Проведение сетевых проверок                           |
| Nmap                   | Сканирование выбранных портов Windows                 |
| Wazuh Dashboard        | Просмотр событий, оповещений и состояния агента       |

## 3. Конфигурация виртуальных машин

### 3.1. Wazuh Server

Сервер мониторинга развёрнут на виртуальной машине с Ubuntu 24.04.5 Desktop.

Ранее зафиксированные параметры виртуальной машины:

| Параметр                           | Значение                     |
| ---------------------------------- | ---------------------------- |
| Операционная система               | Ubuntu 24.04.5 Desktop AMD64 |
| Оперативная память                 | 6144 МБ                      |
| Количество виртуальных процессоров | 4                            |
| Размер виртуального диска          | Около 60 ГБ                  |
| IP-адрес Host-Only                 | `192.168.56.101`             |

На сервере выполняется обработка поступающих событий и предоставляется веб-интерфейс Wazuh Dashboard.

Для работы виртуальной машины использовались сетевые адаптеры NAT и Host-Only: первый предназначен для доступа к внешней сети, второй — для взаимодействия с узлами лаборатории.

### 3.2. Windows 10

Windows 10 используется как контролируемый конечный узел.

| Параметр             | Значение                                          |
| -------------------- | ------------------------------------------------- |
| Операционная система | Windows 10                                        |
| Имя узла             | `DESKTOP-8D6DM90`                                 |
| Wazuh Agent          | Версия 4.14.8                                     |
| Sysmon               | Используется для регистрации системной активности |
| IP-адрес Host-Only   | `192.168.56.102`                                  |

Wazuh Agent обеспечивает передачу настроенных данных на сервер мониторинга. Sysmon регистрирует дополнительные события Windows, в том числе сведения о создании процессов.

В конфигурации агента был указан канал событий Sysmon:

`Microsoft-Windows-Sysmon/Operational`

Наличие этого канала в конфигурации позволяет собирать соответствующие события при условии корректной работы источника и агента.

### 3.3. Kali Linux

Kali Linux используется для проведения контролируемых сетевых проверок конечного узла Windows.

| Параметр                         | Значение         |
| -------------------------------- | ---------------- |
| Операционная система             | Kali Linux       |
| Инструмент                       | Nmap             |
| IP-адрес Host-Only               | `192.168.56.103` |
| NAT-адрес, зафиксированный ранее | `10.0.2.15`      |

С помощью Nmap проверяется состояние выбранных портов тестового Windows-узла. Результаты сканирования позволяют изучить сетевую доступность узла и сопоставить выполненную активность с данными, доступными в Wazuh.

## 4. Сетевая организация

Для взаимодействия виртуальных машин используется Host-Only сеть VirtualBox с адресным пространством `192.168.56.0/24`.

Ранее зафиксированная адресация:

| Узел         | IP-адрес         |
| ------------ | ---------------- |
| Wazuh Server | `192.168.56.101` |
| Windows 10   | `192.168.56.102` |
| Kali Linux   | `192.168.56.103` |

Host-Only сеть обеспечивает взаимодействие узлов в лабораторной среде. NAT используется для отдельного доступа виртуальных машин к внешней сети.

Сетевой обмен между Windows и Wazuh Server необходим для передачи событий агентом. Kali Linux использует лабораторное сетевое соединение для выполнения проверок Windows.

Указанные IP-адреса отражают ранее зафиксированную конфигурацию. При изменении параметров виртуальных машин адреса следует актуализировать.

## 5. Поток событий безопасности

### 5.1. Регистрация событий

Windows регистрирует системные события в журналах операционной системы. Sysmon дополняет стандартные журналы сведениями об определённых действиях, например о создании процессов, в зависимости от своей конфигурации.

### 5.2. Сбор и передача данных

Wazuh Agent получает данные из настроенных источников и передаёт их на сервер мониторинга. Для успешной передачи необходимы корректные настройки агента, доступность сервера и работоспособность соответствующих компонентов.

### 5.3. Анализ событий

Wazuh Server обрабатывает поступившие данные с использованием механизмов анализа и правил обнаружения. При выполнении условий правила может быть сформировано оповещение.

### 5.4. Просмотр результатов

Wazuh Dashboard предоставляет интерфейс для изучения поступивших событий, оповещений и сведений об агенте.

При анализе необходимо различать три результата:

1. Событие зарегистрировано в Windows.
2. Событие передано и доступно для просмотра в Wazuh.
3. Wazuh сформировал оповещение по соответствующему правилу.

Эти результаты не равнозначны. Наличие события в журнале Windows не гарантирует, что оно будет передано в Wazuh или приведёт к созданию оповещения.

## 6. Использование Nmap в лаборатории

Для сетевых проверок с Kali Linux была выполнена команда:

```bash
nmap -Pn -p 135,139,445,3389,5985,5986,80,443 192.168.56.102
```

Назначение параметров:

| Параметр         | Значение                                                                             |
| ---------------- | ------------------------------------------------------------------------------------ |
| `-Pn`            | Не выполнять предварительную проверку доступности узла посредством обнаружения хоста |
| `-p`             | Указать список проверяемых портов                                                    |
| `192.168.56.102` | Адрес тестового Windows-узла                                                         |

В проверку включены порты, связанные с различными сетевыми службами Windows и веб-службами.

Само выполнение сканирования не подтверждает наличие уязвимостей и не гарантирует формирования оповещения Wazuh. Для вывода об обнаружении сетевой активности требуется отдельно изучить результаты сканирования и соответствующие данные на сервере мониторинга.

## 7. Ограничения стенда

* Лаборатория предназначена для обучения и не является промышленной SOC-инфраструктурой.
* Проверки выполняются в контролируемой виртуальной среде.
* Сканирование направлено на собственный тестовый узел Windows.
* Набор собираемых событий зависит от конфигурации Wazuh Agent и Sysmon.
* Не каждое зарегистрированное событие приводит к оповещению.
* Выполненные проверки не подтверждают обнаружение всех возможных угроз.
* Описание конфигурации отражает ранее зафиксированные параметры виртуальных машин; при изменениях его необходимо обновлять.

## 8. Связь архитектуры с результатами проверок

Архитектура определяет, какие компоненты участвуют в регистрации, передаче и анализе событий. Фактические результаты проверок рассматриваются отдельно, чтобы не смешивать описание устройства лаборатории с подтверждением её работы.

Результаты тестирования, наблюдаемые события и доступные подтверждения следует размещать в документе `03-test-results.md` и в каталоге `screenshots/`.

Таким образом, данный документ описывает устройство лаборатории и назначение её компонентов, а результаты проверок позволяют отдельно оценить работу настроенной среды.
